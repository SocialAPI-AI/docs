---

Every failed request to the SocialAPI REST API returns a JSON error with an HTTP status, a stable `error.code`, a human-readable `error.message`, and a `request_id`. Branch on `error.code`, never on `error.message`: messages change, codes do not. This page lists every code a client using an API key or the MCP server can receive.

```json
{
  "error": {
    "code": "validation.field_required",
    "message": "Required field is missing: platform",
    "meta": { "field": "platform" }
  },
  "request_id": "a1b2c3d4"
}
```

| Field | Description |
|---|---|
| `error.code` | A dot-separated code, stable across releases. Match the whole code, or a prefix such as `platform.` or `billing.` |
| `error.message` | A description for logs and display |
| `error.meta` | Structured context, present on some errors. `meta.field` names the invalid input, `meta.max` is set on `automation.limit_reached` and `meta.plan` on `whatsapp.paid_plan_required`, `meta.retry_after_seconds` is how long to wait |
| `request_id` | Identifies the request. It equals the `X-Request-ID` response header |

`request_id` is the `X-Request-ID` request header you sent when it matches `^[a-zA-Z0-9_-]{1,64}$`. Otherwise it is 8 lowercase hexadecimal characters that SocialAPI generates. Quote it in support requests: see [Debugging](/guides/debugging).

A `429` response carries `Retry-After` (in seconds) whenever `error.meta.retry_after_seconds` is present.

**MCP server.** A failed tool call returns `isError: true` and a text result holding JSON: `{"error": "<message>", "code": "<error.code>"}`, with the `error.meta` fields added at the top level. The `code` values are the ones on this page. A request refused before the tool runs, such as an expired token, returns an HTTP error: see [Authentication](/guides/authentication).

## Code namespaces

The first segment of a code tells you which part of the system refused the request.

| Namespace | Meaning |
|---|---|
| `auth.*` | Authentication and authorization |
| `account.*`, `accounts.*` | Connected accounts: lookup, state, Pages, sync |
| `brand.*` | Brand lookup |
| `platform.<name>.*` | The platform (Instagram, TikTok, and the rest) refused the request, or SocialAPI refused it for a platform-specific reason |
| `validation.*` | A request field, parameter, or media item is invalid |
| `resource.*` | Generic lookup, conflict, and capability errors |
| `billing.*` | A plan allowance or plan feature |
| `byok.*` | Your own platform app credentials |
| `publishing.*` | Publishing a post |
| `post.*`, `conversation.*`, `media.*`, `board.*` | Errors on those objects |
| `automation.*` | Automations |
| `whatsapp.*`, `telegram.*`, `google.*` | Errors specific to those platforms |
| `messaging.*`, `inbox.*` | Messaging and sync rate limits |
| `system.internal` | The request failed on SocialAPI's side |
| `http.<status>` | A routing or transport error, such as an unknown path |

One code has no namespace: `ambiguous_post_id`.

## Authentication and access

Every `/v1` request needs `Authorization: Bearer <API key>`. See [Authentication](/guides/authentication) and [Scoped API keys](/guides/scoped-keys).

| HTTP | Code | When it occurs |
|---|---|---|
| 401 | `auth.missing_header` | The `Authorization` header is absent |
| 401 | `auth.empty_token` | The header is `Authorization: Bearer` with no token |
| 401 | `auth.invalid_key` | The API key does not exist, was revoked, or was rotated away |
| 401 | `auth.invalid_token` | The bearer token is neither a valid API key nor a valid OAuth 2.1 access token, or it has expired |
| 401 | `auth.user_not_found` | The token belongs to a SocialAPI account that no longer exists |
| 403 | `auth.insufficient_scope` | A [scoped API key](/guides/scoped-keys) lacks the scope the request needs, or a scoped key called an admin operation (managing keys, brands, invites, or `PATCH /v1/users/me`). `meta.required_scope` names the scope when one applies |
| 402 | `billing.past_due` | Your subscription payment failed twice. Every endpoint returns it except every method of `/v1/users/me` and every `/v1/billing/*` endpoint. See [Past-due accounts](/guides/plans#past-due-accounts) for how access returns |
| 403 | `auth.state_mismatch` | The `state` you passed to a connect step belongs to a different API key |
| 400 | `auth.oauth.invalid_client` | The MCP client's `client_id` is unknown. See [OAuth for MCP clients](/integrations/oauth) |
| 400 | `auth.oauth.invalid_redirect` | The MCP client's `redirect_uri` is not registered for its `client_id` |

The `/oauth/token` endpoint answers errors in the OAuth format (`error`, `error_description`) instead of this envelope: see [OAuth for MCP clients](/integrations/oauth#token-endpoint-errors).

## Request validation

These codes apply to any endpoint. `error.meta.field` names the offending input when the input is a single field.

| HTTP | Code | When it occurs |
|---|---|---|
| 400 | `validation.body_invalid` | The request body is not valid JSON, or has the wrong shape |
| 400 | `validation.field_required` | A required field is missing. `meta.field` names it |
| 400 | `validation.field_invalid` | A field or parameter has the wrong type, format, or value. `meta.field` names it. Examples: `from` is not RFC 3339, `cursor` is malformed, a webhook `url` is not an `https` URL, a webhook event type is unknown, a media `url` is not a public `http` or `https` address, `scheduled_at` is in the past on a post with targets |
| 400 | `validation.id_invalid` | A comment or review ID in the path is neither a platform ID nor a SocialAPI ID |
| 400 | `validation.id_platform_mismatch` | A comment or review ID belongs to a different platform than the `account_id` |

## Not found, conflicts, and unsupported operations

| HTTP | Code | When it occurs |
|---|---|---|
| 404 | `resource.not_found` | The object does not exist or is not visible to your key. `meta.resource` names the type (for example `post`, `automation`, `brand`) and `meta.id` the ID |
| 404 | `account.not_found` | The `acc_` ID is not a connected account of your SocialAPI account |
| 404 | `brand.not_found` | The brand is outside the brands your [brand-restricted key](/guides/scoped-keys) can reach |
| 404 | `conversation.not_found` | The conversation does not exist or is not yours |
| 404 | `media.not_found` | The media item does not exist or is not yours |
| 409 | `resource.conflict` | The request conflicts with current state. Duplicate post content and invite creation use it: see below |
| 409 | `ambiguous_post_id` | The platform post ID you passed matches more than one post. Use the SocialAPI post ID |
| 501 | `resource.not_supported` | The operation does not exist on this account's platform. `meta.platform` names it. See the [capability matrix](/platforms/overview) |
| 422 | `account.platform_unsupported` | The account's platform has no reviews, and the request was for reviews |
| 4xx, 5xx | `http.<status>` | A routing or transport error. `http.404` is an unknown path. `GET /v1/inbox/media/{id}` also returns `http.404` (unknown media), `http.410` (media expired), `http.503` (too many waiting requests, retry after 1 second), and `http.504` (media still being fetched, send the request again until you get 200 or 410) |

## Rate limits

Rate-limit codes are `429` and are covered in [Rate limits](/guides/rate-limits), which says what each limit counts and how to retry.

| HTTP | Code | When it occurs |
|---|---|---|
| 429 | `publishing.velocity_limit` | A publish target reached its post cap per hour or per 24 hours. `meta.window` is `hour` or `day` |
| 429 | `messaging.velocity_limit` | A sender (Instagram account, Facebook Page, or WhatsApp phone number) reached its cap of messages per minute. Nothing was sent |
| 429 | `platform.<name>.rate_limit` | The platform's own limit. Wait, then retry with backoff. Credit rules: see [when a credit comes back](/guides/plans#when-a-credit-comes-back) |
| 429 | `inbox.sync_rate_limited` | `POST /v1/inbox/sync` ran again before the wait for the same target ended. `meta.retry_after_seconds` is set |
| 429 | `accounts.sync_rate_limited` | `POST /v1/accounts/{id}/sync` ran again before the wait for the same account ended. `meta.retry_after_seconds` is set |

## Delivery failures

A target that fails after `POST /v1/posts` returned is a failed delivery. It does not return an HTTP error. Its code is in `targets[].error.code` on the post (`GET /v1/posts/{pid}`) and in `results[].error.code` of the `post.failed` and `post.partial` webhooks. `GET /v1/events` has no error code. See [Delivery](/guides/delivery#target-errors).

| Code | When it occurs |
|---|---|
| `publishing.delivery.account_load_failed` | SocialAPI could not load the connected account when the delivery ran |
| `publishing.delivery.page_resolve_failed` | SocialAPI could not resolve the target's Facebook Page |
| `publishing.delivery.timeout` | Sending did not finish within 15 minutes |
| `validation.publish` | The post failed validation when the delivery ran, after the request had been accepted |
| `platform.<name>.publish_failed` | The platform failed the publish and gave no code SocialAPI maps |
| `platform.<name>.<code>` | Any [platform error](#platform-errors) the platform raised during the publish |
| `system.internal` | The target never finished, or a SocialAPI error stopped it |

## Platform errors

When a platform refuses a call, the code is `platform.<name>.<reason>`, where `<name>` is the platform slug. SocialAPI forwards the platform's HTTP status when it maps one, and returns `502` otherwise.

| HTTP | Code | When it occurs |
|---|---|---|
| 401 | `platform.<name>.auth` | The platform rejected the saved token. Reconnect the account |
| 403 | `platform.<name>.insufficient_scope` | The token lacks a permission the call needs. Reconnect the account to grant it. `error.message` names the permission when known |
| 401 | `platform.<name>.unauthorized` | The platform answered 401 without saying the token is bad. A healthy account keeps working. Reconnect if it persists |
| 429 | `platform.<name>.rate_limit` | The platform's own limit. See [Rate limits](#rate-limits) |
| 422 | `platform.<name>.publish_failed` | A publish failed with an error SocialAPI does not map. Appears in [Delivery failures](#delivery-failures) |
| 502 | `platform.<name>.api_error` | A failure reaching the platform, or a response with no usable error |
| 502 | `platform.<name>.<code>` | The platform returned its own error code, such as `platform.facebook.100`. The status is `502` unless the platform's code maps to another status |

Branch on the prefix and suffix: `platform.` with `.auth` means reconnect, with `.rate_limit` means back off.

## Handling errors

Read `error.code` from the response, then branch. Reconnect on a dead token, back off on a throttle, show the field on a validation failure, and log `request_id` for anything else.

```typescript
const resp = await fetch("https://api.social-api.ai/v1/accounts", {
  headers: { Authorization: `Bearer ${process.env.SOCAPI_KEY}` },
});

if (!resp.ok) {
  const { error, request_id } = await resp.json();
  const { code, message, meta } = error;

  if (code === "account.reconnection_required" ||
      (code.startsWith("platform.") && code.endsWith(".auth"))) {
    return reconnect(); // POST /v1/accounts/connect
  }
  if (resp.status === 429 && meta?.retry_after_seconds) {
    await sleep(meta.retry_after_seconds * 1000);
    return retry();
  }
  if (code.startsWith("validation.")) {
    return showFieldError(meta?.field, message);
  }
  throw new Error(`${code}: ${message} (request_id ${request_id})`);
}
```

For a `429` without `meta.retry_after_seconds` (a platform limit), wait and retry with backoff. A plan allowance such as `validation.post_limit_exhausted` does not clear until the billing period ends: check `GET /v1/usage`.
