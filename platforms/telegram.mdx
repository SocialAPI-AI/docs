SocialAPI connects a Telegram bot that you create with @BotFather and reads and answers the direct messages (DMs) people send to it. You connect the bot with its token: there is no OAuth, no Telegram developer account, and no app to register. On Telegram, SocialAPI supports direct messages and nothing else: it offers no posts, comments, reviews, or mentions for Telegram. [Platform apps](/guides/platform-credentials) lists which app connects each platform.

## At a glance

| Field | Value |
|---|---|
| Platform slug | `telegram` |
| Auth | Bot token from @BotFather |
| Platform API | Telegram Bot API |
| Status | Available on every plan |

## Capabilities

| Feature | Supported | Notes |
|---|---|---|
| Receive DMs | Yes | Messages people send to your bot in a private chat arrive as `dm.received` webhook events and in the inbox. See [Receive messages](/platforms/telegram/messages#receive-messages) |
| Send DMs | Conditional | Only to a person who has messaged the bot first. Otherwise the send fails with `403 telegram.cannot_message`. See [Who you can message](/platforms/telegram/messages#who-you-can-message) |
| DM attachments | Yes | One file per message, sent as a photo or a document. `platform_attachment_id` is not supported |
| Group chats and channels | No | SocialAPI supports private chats between a person and your bot. Messages from a group can still appear in the inbox, and a reply never reaches the group. See [Who you can message](/platforms/telegram/messages#who-you-can-message) |
| Buttons, quick replies, cards, and lists | No | SocialAPI drops `quick_replies`, `buttons`, `cards`, and `list_sections` and sends the `text` and attachments. Without `text`, the request fails with `400 validation.telegram_bad_request` |
| Message history | No | Telegram gives bots no message history. The inbox starts with the messages Telegram delivers once the bot is connected, including messages up to 24 hours old that no other service received |
| Message reactions | No | Returns `501 resource.not_supported` |
| Typing indicators and seen receipts | No | Returns `501 resource.not_supported` |
| Comments | No | Returns `501 resource.not_supported` |
| Mentions | No | Returns `501 resource.not_supported` |
| Reviews | No | Telegram has no reviews. Returns `422 account.platform_unsupported` |
| Publishing | No | `POST /v1/posts` and `PATCH /v1/posts/{post_id}` with a Telegram target return `422 account.platform_unsupported` |
| Automations | No | Automations run on Instagram and Facebook accounts only. `422 automation.platform_unsupported` |

The capability matrix for every platform is on [Supported platforms](/platforms/overview).

## Connect a bot

A Telegram bot connects in one request: you send its token, and SocialAPI returns the connected account.

<Steps>
  <Step title="Create the bot">
    Open Telegram and message [@BotFather](https://t.me/BotFather). Send `/newbot`, choose a display name, then choose a username that ends in `bot`.
  </Step>
  <Step title="Copy the token">
    BotFather replies with a token of the form `123456789:ABCdefGhIjKlMnOpQrStUvWxYz-1234`. Anyone who holds the token controls the bot, so keep it secret.
  </Step>
  <Step title="Connect the bot">
    Send the token as `metadata.bot_token`:

    ```bash
    curl -X POST https://api.social-api.ai/v1/accounts/connect \
      -H "Authorization: Bearer $SOCAPI_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "platform": "telegram",
        "metadata": { "bot_token": "123456789:ABCdefGhIjKlMnOpQrStUvWxYz-1234" }
      }'
    ```

    Response (HTTP 201):

    ```json
    {
      "account_id": "acc_01HZ9X3Q4R5M6N7P8V2K0W1J",
      "brand_id": "1c9f6f0e-2b3a-4c5d-8e7f-0a1b2c3d4e5f",
      "platform": "telegram",
      "username": "acme_support_bot",
      "display_name": "Acme Support"
    }
    ```
  </Step>
</Steps>

`username` is the bot's username and `display_name` is its name. Without `brand_id` in the request, SocialAPI creates a brand for the bot. SocialAPI also sends `account.connected` to your webhook endpoints.

A missing `bot_token` returns `400 validation.field_required`. A token Telegram rejects returns `401 platform.telegram.auth`.

### One bot, one receiver

Connecting the bot points its Telegram webhook at SocialAPI and replaces any webhook the bot already had. Telegram delivers a bot's updates to one receiver only: while the bot is connected to SocialAPI, another service cannot receive its messages by webhook or with `getUpdates`.

Disconnecting the account (`DELETE /v1/accounts/{account_id}`) removes the webhook, so Telegram stops sending the bot's messages to SocialAPI. The token itself stays valid until you revoke it with `/revoke` in @BotFather. A bot token has no expiry date. After a revoke, connect the bot again with the new token: see [Reconnect an account](/guides/connect-accounts#reconnect-an-account).

## Direct messages

People start a private chat with your bot, and you read and answer their messages with the same conversation endpoints as every other platform. Once a person has written to the bot, the bot can answer at any time, and the bot can never write first. Message types, attachments, size limits, and errors are on [Telegram direct messages](/platforms/telegram/messages).

## Webhook events

A Telegram account sends these events to your [webhook endpoints](/guides/webhooks):

| Event | When it fires |
|---|---|
| `account.connected` | You connected the bot |
| `dm.received` | A person sent a message to the bot. The Telegram payload is in [Receive messages](/platforms/telegram/messages#receive-messages) |

A Telegram account emits no other event. The payloads are on [Webhook events](/guides/webhook-events).

## Scopes

A Telegram bot has no OAuth scopes. The bot token gives full control of the bot, and SocialAPI uses it to receive the bot's messages and to send replies. The account supports the `messages.read` and `messages.write` [permissions](/guides/permissions), which SocialAPI alone enforces.
