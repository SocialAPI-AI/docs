Connect SocialAPI to [OpenClaw](https://docs.openclaw.ai) so the agents behind every channel you route through the OpenClaw gateway can list your connected accounts, reply to comments, send DMs, and publish posts. OpenClaw keeps its MCP servers in `~/.openclaw/openclaw.json` under `mcp.servers`. The server is `https://api.social-api.ai/mcp`.

## Prerequisites

- OpenClaw installed (`npm i -g openclaw`).
- A SocialAPI account with at least one connected account.
- For a gateway with no browser: an [API key](/integrations/custom).

## Set up with OAuth

<Steps>
  <Step title="Add the server">
    ```bash
    openclaw mcp add socialapi \
      --url https://api.social-api.ai/mcp \
      --transport streamable-http \
      --auth oauth
    ```

    This saves the entry to `~/.openclaw/openclaw.json`:

    ```json
    {
      "mcp": {
        "servers": {
          "socialapi": {
            "url": "https://api.social-api.ai/mcp",
            "transport": "streamable-http",
            "auth": "oauth"
          }
        }
      }
    }
    ```

    Set `transport` to `streamable-http`. When you omit it, OpenClaw uses SSE.
  </Step>
  <Step title="Sign in">
    ```bash
    openclaw mcp login socialapi
    ```

    OpenClaw prints an authorization URL and waits for the browser callback on `127.0.0.1:8989`. Open the URL, log in to SocialAPI, and click **Authorize**. The terminal prints `MCP OAuth credentials saved for "socialapi"`.

    If the gateway runs on another machine and the callback cannot reach it, authorize in your browser, copy the `code` from the redirect URL, and finish with:

    ```bash
    openclaw mcp login socialapi --code <code>
    ```
  </Step>
  <Step title="Check the server">
    ```bash
    openclaw mcp probe socialapi
    ```

    OpenClaw connects and reports the number of tools. If the gateway is already running, `openclaw mcp reload` picks up the new server without a restart.
  </Step>
</Steps>

## Choose shared or per-sender accounts

By default, the credentials from `openclaw mcp login` are shared: every channel acts on the one SocialAPI account you authorized. Use this for a personal assistant or a team bot.

To let each person who messages the agent connect their own SocialAPI account, set `oauth.identity` to `per-requester` and give the gateway a public HTTPS origin for the callback:

```json
{
  "gateway": {
    "publicOrigin": "https://gateway.example.com"
  },
  "mcp": {
    "servers": {
      "socialapi": {
        "url": "https://api.social-api.ai/mcp",
        "transport": "streamable-http",
        "auth": "oauth",
        "oauth": { "identity": "per-requester" }
      }
    }
  }
}
```

The first time a sender calls a SocialAPI tool, OpenClaw replies with a sign-in link for that sender.

## Set up a headless gateway with an API key

OpenClaw ignores a static `Authorization` header while `auth` is `oauth`, so save the server without `auth`:

<Steps>
  <Step title="Set the variable">
    ```bash
    export SOCIALAPI_API_KEY=sapi_key_xxxxxxxxxxxxxxxx
    ```
  </Step>
  <Step title="Save the server">
    ```bash
    openclaw mcp set socialapi '{"url":"https://api.social-api.ai/mcp","transport":"streamable-http","headers":{"Authorization":"Bearer ${SOCIALAPI_API_KEY}"}}'
    ```

    OpenClaw resolves `${SOCIALAPI_API_KEY}` from the environment the gateway runs in, so the key never sits in `openclaw.json`. To limit what the agent can do, create a [scoped API key](/guides/scoped-keys).
  </Step>
</Steps>

## Limit the tools

Hide the tools that a channel agent must never call:

```bash
openclaw mcp tools socialapi --exclude 'social_api_delete_*,social_api_disconnect_account,social_api_revoke_key'
```

Use `--include` to keep only a subset instead, and `--clear` to remove the filter. See [MCP tools reference](/integrations/tools) for every tool name.

## Try it

Send the agent a message on any routed channel:

```text
List my connected social accounts
```

The agent calls `social_api_list_accounts` and answers with your connected accounts and their platforms.

## Troubleshooting

<AccordionGroup>
  <Accordion title="listen EADDRINUSE: address already in use 127.0.0.1:8989">
    Another `openclaw mcp login` is still waiting. Stop it, or finish with `--code <code>` as shown above.
  </Accordion>
  <Accordion title="requires OAuth authorization">
    The server is saved but not signed in. Run `openclaw mcp login socialapi`.
  </Accordion>
  <Accordion title="Streamable HTTP error with an API key">
    The key is wrong or revoked, or the variable is not set where the gateway runs. Check the key in the [dashboard](https://app.social-api.ai/api-configuration?tab=keys).
  </Accordion>
</AccordionGroup>
