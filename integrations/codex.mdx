Connect SocialAPI to Codex and ask it to list your connected accounts, reply to comments, send DMs, and publish posts. Codex reads MCP servers from `~/.codex/config.toml`. The Codex CLI, the Codex IDE extension, and the ChatGPT desktop app share that file, so one entry gives every Codex session the SocialAPI tools. The server is `https://api.social-api.ai/mcp`.

## Prerequisites

- [Codex](https://developers.openai.com/codex) installed: CLI, IDE extension, or desktop app.
- A SocialAPI account with at least one connected account.
- For a machine without a browser: an [API key](/integrations/custom).

## Set up with the CLI

<Steps>
  <Step title="Add the server">
    ```bash
    codex mcp add socialapi --url https://api.social-api.ai/mcp
    ```

    Codex saves the server, detects that it uses OAuth 2.1 with PKCE, and opens your browser on the SocialAPI authorization page. Codex stores no API key and refreshes the token itself.
  </Step>
  <Step title="Authorize">
    Log in and click **Authorize**. The terminal prints `Successfully logged in to MCP server 'socialapi'`.
  </Step>
  <Step title="Check the server">
    ```bash
    codex mcp list
    ```

    `socialapi` is listed as `enabled` with its auth method. In the Codex TUI, type `/mcp` to see the connected servers and their tools.
  </Step>
</Steps>

To sign in again on a new machine or after a revoked session, run `codex mcp login socialapi`.

## Set up with the config file

<Steps>
  <Step title="Add the entry">
    `codex mcp add` writes this entry to `~/.codex/config.toml`. You can also add it by hand, globally or in a trusted project's `.codex/config.toml`:

    ```toml
    [mcp_servers.socialapi]
    url = "https://api.social-api.ai/mcp"
    ```
  </Step>
  <Step title="Authorize">
    ```bash
    codex mcp login socialapi
    ```
  </Step>
</Steps>

## Set up a headless machine with an API key

For CI jobs, containers, and any machine without a browser, skip OAuth and authenticate with an API key. Codex reads the key from an environment variable and sends it as `Authorization: Bearer`.

<Steps>
  <Step title="Reference the variable">
    ```toml
    [mcp_servers.socialapi]
    url = "https://api.social-api.ai/mcp"
    bearer_token_env_var = "SOCIALAPI_API_KEY"
    ```
  </Step>
  <Step title="Set the variable">
    ```bash
    export SOCIALAPI_API_KEY=sapi_key_xxxxxxxxxxxxxxxx
    ```
  </Step>
</Steps>

<Warning>
  Keep the key in the environment or a secret manager. Never paste it into `config.toml` or commit it. To limit what the agent can do, create a [scoped API key](/guides/scoped-keys).
</Warning>

## Limit the tools

To give Codex fewer tools, list the ones to keep in `enabled_tools`, or the ones to hide in `disabled_tools`. Codex applies `disabled_tools` after `enabled_tools`:

```toml
[mcp_servers.socialapi]
url = "https://api.social-api.ai/mcp"
disabled_tools = [
  "social_api_delete_post",
  "social_api_delete_comment",
  "social_api_disconnect_account",
  "social_api_revoke_key",
]
```

See [MCP tools reference](/integrations/tools) for every tool name.

## Try it

Ask Codex:

```text
List my connected social accounts
```

Codex calls `social_api_list_accounts` and answers with your connected accounts and their platforms.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The browser does not open">
    Codex prints the authorization URL (`Authorize socialapi by opening this URL in your browser`). Open it on the same machine: the callback goes to a local port that Codex listens on.
  </Accordion>
  <Accordion title="HTTP 401 with an API key">
    The variable named in `bearer_token_env_var` is not set in the shell that started Codex, or the key is revoked. Check the key in the [dashboard](https://app.social-api.ai/api-configuration?tab=keys).
  </Accordion>
  <Accordion title="Tools are missing in the IDE extension or desktop app">
    They read the same `~/.codex/config.toml`. Restart the app after you edit the file.
  </Accordion>
</AccordionGroup>
